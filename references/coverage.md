# Поиск существующего покрытия

Сначала определить базу по [маршруту проекта](project-context.md), при нехватке
данных спросить пользователя. Использовать выбранный `project_context.case_project`.
Не угадывать TMS-проект по названию задачи. Для существующего кейса проверить проект
из его ссылки/записи. Если база неизвестна или недоступна, поиск — `unavailable`,
а не «совпадений нет». `not_applicable` допустим только при подтверждённом отсутствии базы.

Для новой или изменяющей пользовательский путь проверки искать среди всех актуальных
кейсов выбранной базы, включая релевантные drafts; не ограничиваться связями с задачей.
Искать по названию, описанию, предусловиям и шагам, включая раскрытые общие условия.

Использовать минимум два независимо сформулированных запроса: например, доменная
сущность и пользовательское действие, затем результат и другой вариант терминологии.
Учитывать синонимы и словоформы. Технические признаки брать только из источников.
Совпадение слов — кандидат, а не доказательство одинакового покрытия.

Открыть потенциально покрывающие кейсы целиком и сравнить:

| Признак | Вопрос |
|---|---|
| Исходное состояние | Совпадают данные, доступы и точка входа? |
| Действия | Это тот же пользовательский путь? |
| Результат | Защищается тот же риск? |
| Варианты | Уже есть нужная параметризация или её можно добавить? |

Результат поиска должен содержать область, источники, запросы, рассмотренных кандидатов,
ссылки/ID и ограничения полноты. Нельзя объявить отсутствие покрытия по первой странице,
заголовкам, недоступному кандидату или упавшему поиску. Для полной выгрузки проверить
пагинацию, ограничения сервера и доступность полного текста. Большой корпус хранить
локально и читать выборочно; не помещать всю базу в контекст модели.

Если основной поддержанный способ поиска недоступен, использовать доступный резервный
клиент или экспорт, явно проверив область и актуальность. Отказ обоих источников —
ограничение поиска, не разрешение создать новый кейс. Локальные предложения возможны
со статусом `blocked`; раннее превью — только по запросу соответствующего режима.

Если пользователь явно сообщил, что базы кейсов ещё нет, зафиксировать это как
`not_applicable` с основанием, а не имитировать поиск и выдумывать найденные ID.
Для чисто редакторского изменения без смены смысла достаточно полного чтения текущего
кейса: область поиска `targeted`, с объяснением границы правки.

Остановить discovery, когда сравнение полного текста и доступное подтверждение позволяют
выбрать действие. Не расширять поиск ради объёма. Перед записью перечитать выбранный
кейс; при известных конкурентных изменениях обновить сравнение и поиск.
