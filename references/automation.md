# Анализ существующей автоматизации

Для каждого создаваемого и изменяемого сценария определить, какие проверки уже
защищают его риск. Для решения `unchanged` отдельный поиск только ради отчёта не нужен.

Использовать репозитории из `project_context.automation_repositories`, определённые
по [маршруту проекта](project-context.md). Если источник ещё неизвестен, сначала
уточнить у пользователя, где искать код. Не принимать текущую рабочую папку за
репозиторий продукта автоматически. Код продукта и E2E могут храниться отдельно.
Если пользователь подтвердил отсутствие репозитория либо не может предоставить
доступ, записать причину и действие `blocked`; не утверждать, что автотестов нет.

Изучить конфигурацию и близкие тесты, определить реальные слои проекта. Искать в
явно выбранных каталогах по сущности, действиям, API, компонентам и изменённому коду.
Название кейса использовать лишь как один из запросов. Не сканировать весь монорепозиторий.

Проверять только применимые слои: E2E, API, интеграционные, компонентные, визуальные,
unit или другие принятые в проекте. Ни один конкретный фреймворк не является обязательным.
Открыть кандидатов и сопоставить assertions с действиями и результатами кейса.
Файл теста не доказывает ни покрытие всего пути, ни успешность его выполнения.

Зафиксировать реально просмотренные области, найденные проверки с точными путями,
границы покрытия и пробелы. Остановить поиск, когда применимые слои просмотрены и
доказательств достаточно. Не запускать тесты только ради факта их наличия.

Одно рекомендованное действие:

- `add` — добавить проверку конкретного непокрытого риска;
- `update` — дополнить существующую проверку для указанного пробела;
- `covered` — найденное покрытие защищает существенный риск сценария;
- `not_needed` — автоматизация не даёт разумной регрессионной ценности;
- `blocked` — кода или контекста недостаточно для честного вывода.

Для `add`/`update` назвать пробел и подходящий слой. При недоступном репозитории
использовать `blocked`, а не «автотестов нет». Это ограничение анализа автоматизации
не отменяет подтверждённый ручной проход. Не менять тесты и не создавать задачи
без отдельного поручения.
