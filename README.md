# Write Reproducible Test Cases

Скилл для агента, который пишет и актуализирует тест-кейсы по требованиям и
подтверждённому пользовательскому пути. Основной результат — локальные Markdown-кейсы,
журнал прохождения, необходимые изображения и краткий отчёт о покрытии и ограничениях.

## Как попробовать

Подключите эту папку как локальный скилл в агенте, поддерживающем `SKILL.md`,
или явно передайте агенту путь к `SKILL.md`. Инструкции написаны на русском;
язык создаваемых кейсов определяется запросом и практикой проекта.

Пример запроса:

> Используй скилл write-reproducible-test-cases из этой папки.
> Требования: requirements.md. Существующие кейсы: tests/manual/.
> Приложение: адрес тестовой среды. Код для анализа автопокрытия: путь к проекту.
> Подтверди пользовательский путь в браузере и сохрани результат в отдельный каталог.
> Во внешние системы ничего не записывай.

Нужны доступ к требованиям, текущему покрытию и приложению, а также браузерный
инструмент агента. Вместо нового прохода можно предоставить подробный актуальный
отчёт с проверяемыми артефактами. Конкретный браузерный CLI или MCP-сервер не включён
в пакет и не устанавливается автоматически. Для renderer достаточно Python 3.10+,
без дополнительных библиотек.

Если ссылки на кейсы или код не переданы, агент сначала ищет однозначные привязки
в доступных материалах проекта, затем спрашивает пользователя о недостающем:
где хранится база кейсов и в каком репозитории/каталоге искать автотесты. Ответ
сохраняется в контексте текущей задачи. Поддерживаются отдельные репозитории продукта
и E2E, любая TMS, экспорт и локальная папка с кейсами. Текущая рабочая папка не
считается репозиторием продукта автоматически. Подробности:
[определение проекта](references/project-context.md).

Один из вариантов браузерного инструмента — [Playwright CLI](https://github.com/microsoft/playwright-cli).
Через него агент может открывать страницы, выполнять действия, получать состояние
интерфейса, сохранять скриншоты и трассировку. Он рассчитан на работу с кодинг-агентами:
[официальная документация](https://playwright.dev/agent-cli/introduction).
Можно выбрать другой доступный инструмент с подходящими возможностями; если его
нет, агент уточняет способ запуска, а не отмечает сценарий пройденным.

Если базы кейсов ещё нет, укажите это явно. Если приложения пока нет, запросите
раннее превью: оно будет помечено как непроверенное и не попадёт в постоянную регрессию.
Для неизвестных предусловий, отсутствующего доступа и недоступных источников агент
сохранит ограничения вместо выдуманного успешного прохода.

## Принцип

Требования задают ожидания; проход приложения подтверждает исполнимость в конкретных
условиях. Сначала проверяется существующее покрытие, затем выбирается дополнение
или новый сценарий. Скриншоты дополняют журнал действий, а не заменяют его.

Подробный процесс: [SKILL.md](SKILL.md). Формат данных и команда проверки:
[references/output.md](references/output.md).

`scripts/finalize_cases.py` проверяет согласованность результата и наличие локальных
артефактов, формирует Markdown. Он не управляет браузером и не доказывает достоверность
evidence, полноту требований или независимую воспроизводимость другим исполнителем.
Подключение к внешней TMS возможно через имеющийся поддержанный клиент, по отдельному
разрешению на запись и с последующим чтением результата.

В пакет не входят корпоративные сервисы, внутренние адреса, данные проектов,
учётные записи или секреты. Он подготовлен для локального опробования; сравнение
качества на реальных проектах не входит в проверку упаковки.

Проверка helper на синтетических данных (без сети и браузера):

```bash
python3 -m unittest discover -s tests -v
```
